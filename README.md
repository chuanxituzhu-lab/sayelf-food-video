## 开始使用

1. 解压 ZIP，双击 `sayelf-food-video.html`，用桌面浏览器打开。
2. 普通用户先输入事件/故事线索，再选择菜品和场景，点击“一键生成创作方案”；也可以在菜品框输入新的菜品名称，系统会按事件与工艺决定节点、分镜数量、镜头与节奏。
3. 品牌重复使用时，在“品牌知识库”选择档案并点击“调用品牌档案”；第一次使用可在专业设置中保存当前品牌的口吻、视觉规则和连续性规则。档案只保存在本机。
4. 需要精细控制时，打开“专业用户：打开高级设置”，可调整事件证据、四要素表达覆盖、菜品或自定义菜名、品牌/门店、创意主题、场景补充、平台、时长、故事性、参考说明和画面比例（自动匹配、9:16、3:4、16:9、4:5）。参照照片可在本机选择并预览，文件不会上传。
5. 查看分镜、图片 Prompt 和视频 Prompt；普通用户可复制内容或下载 TXT。校验结果、冻结母结构、导入配置与下载配置 JSON 收纳在专业用户折叠区。

6. 顶部语言菜单可切换中文 / English。切换只改变界面和内置模板；你填写的品牌、台词、事件和创意保持原文。生成记录默认折叠在结果区，失败输入不会覆盖上一份通过校验的方案，可用“恢复上一份有效方案”继续工作。

无需后端、安装包、API key、模型下载或网络连接。所有运算均为浏览器本地确定性规则。品牌知识库使用浏览器本机存储，支持显式导入/导出；普通输入仍不自动保存。JSON 保存输入，TXT 保存双提示词。

**功能边界**：此版本生成图片/视频提示词及拍摄方案，不直接生成图片、音乐或 MP4。没有爆款保证。将 Prompt 手动交给目标生成器时，再绑定获授权参考素材并检查该工具的格式、单次时长与费用；本页不会替你发送内容。

## 事件先行与镜头表达

来源为用户提供、已在本次本地审看的两张课堂截图：

`主体（拍什么） + 动态（做什么） + 镜头（怎么拍） + 风格（定调）` 是表达语言，不是分镜的起点。

主入口是事件/故事线索。编译器先读取事件和已填写的事件节点，再形成 beat 序列并决定分镜数量，最后按动作完成度分配时间；主体、动态、镜头、风格只负责表达这些节点。没有事件时回退到菜品工艺阶段，并明确标为拍摄建议。默认按内容动态分工；专业用户可切换“手动约束”，此时才要求四要素全部填写。两种模式都从同一份 `shots` 结果生成图像帧和视频分镜。

普通镜头以约 2 秒作为节奏参考，不是固定时长。实际 `start/end` 先服从故事节点和总时长，再由动作完成度、情绪停顿、热油/收汁和成品展示决定；因此同一条视频里可以有接近 2 秒的常规镜头，也可以有更长的关键镜头或更短的承接镜头。这个“先故事、后时间”的做法与 [ACMI 分镜教学](https://www.acmi.net.au/education/school-program-and-resources/film-it-storyboards/) 和 [奥斯卡电影剪辑活动指南](https://www.oscars.org/sites/oscars/files/complet_film_editing_activities_guide.pdf?VersionId=p3p.tRvUBbm9e3U9KQ5c_sFHQNewKYUS) 中按动作、事件和叙事目的安排时长的思路一致。

事件线索可以只写一句，也可以在专业区补充小缺点、实际影响、人物分歧、可见情绪、老板决断、责任动作和下一集问题。字段越完整，事件序列越长；缺失字段不会由程序编造成事实。完整母结构是用户明确选择的专业例外，仍按固定十节点输出。

本版继续吸收两张课堂参考图的编排手法：先给料理卡（食材、做法、工艺序列和时间逻辑），再给动作级镜头面板；每镜单独写镜头运动、剪辑承接、现场声和自然视觉效果，并用角色/场景锚点与负面约束保护一致性。参考图只作为结构观察，不复制其中的图片、文字、人物或具体成片设定。

视频使用截图中的 Seedance 风格结构：参考说明 `@图1` / `@音频1` → 按 0–2、2–4、4–6 秒等连续时段编排镜头 → 可选台词与风格 → 无BGM/无字幕/无画面水印等约束。这里是文本编排风格，不是官方 API 接口承诺，也未调用 Seedance。

图片出口包含封面关键帧与各镜关键帧；视频出口包含时间段、动作、角度、运镜、方向、情绪、声音、依据标签与一致性约束。运镜按“角度 × 移动方式 × 方向”编排，单个输出不产生完全重复的运镜描述，并按选材、处理、烹制、滋啦、盛盘等节点突出不同重点。分镜预览中的每张卡片默认折叠该镜 Prompt，点击“查看该镜 Prompt”即可展开，并可单独复制。每次生成都会验证 `imageFrames.length === shots.length`，图片关键帧和视频分镜逐一共享编号与时间。单次长片能力取决于外部工具，可按分镜分段生成再剪辑。

## 真实创业故事

账号定位会随菜品自动变化：油泼面为“油泼面创业真人秀”，回锅肉为“川菜后厨掌勺真人秀”，火锅为“火锅店创业真人秀”，小面为“小面摊创业真人秀”，其余菜品也有对应的制作场景人设。共同底线仍是光鲜 × 狼狈、雷霆手段 × 菩萨心肠；对品质较真，不制造假冲突。

母结构参考：真实事件 → 小缺点 → 放大矛盾 → 人物冲突 → 情绪拉满 → 老板决断 → 人性反转 → 滋啦一声 → 美食奖励 → 留下下一集问题；普通切片只选事件实际需要的节点。

- 切片选择少量节点；不要求每条装满全部元素。
- 完整模式须开启真人秀且至少 20 秒；更短时自动改为切片。
- 事件描述与确认缺一时，输出“待拍摄建议”。有事件但没有冲突、决断或反转依据时，对应节点用中性动作替代。
- 高冲突强度调整动作节奏、停顿与现有分歧，不自动制造指责、争吵或损失。
- 十一个内置示范均是创作设定，素材确认默认关闭，不携带客户事件、课堂原图或原会话附件。
- 用户声明不等于机器核实。勾选确认并不能防止错误陈述；程序不具备测谎或自动识别全部虚构内容的能力。
- 真实事件进入 AI 画面工具后生成的画面仍是生成内容，不是现场证据。

川菜系列已内置六道菜的工艺链：回锅肉、鱼香肉丝、毛血旺、麻婆豆腐、水煮鱼、夫妻肺片。每道菜都按选材 → 处理 → 烹制 → 盛盘（或指定器皿）提供动作、器皿、色彩、现场声和场景转场建议；场景模式为“自动匹配”时沿用该菜的案台→灶台→出菜路线，指定其他场景时保留食材与器物锚点，并给出转换承接方式。分镜时长不足时会合并相邻工艺，但末镜一定落到盛盘/出菜。

菜品栏支持直接输入新名称。已收录菜品使用专属词库；自定义菜名采用“选材 → 处理 → 烹制 → 盛盘”的川味通用工艺、器皿和场景路线，并在结果中标注为通用建议，方便专业用户继续补充具体做法。

## 声音与画面控制

无BGM保留现场声；关闭 ASMR 只取消强化，不必静音。油泼面强调滋啦，火锅强调沸腾，小面强调拌面，精致菜强调落盘，街头小吃强调煎烤。开启配乐时提供氛围建议，不附带未经授权的音乐文件。

无字幕、无水印是 Prompt 中的要求；本工具不能控制供应商固定水印或验证最终视频。原话按每秒约 4 汉字估算时长，放不下则省略并提示，禁止为了填时长补造原话。

## FDE 现场交付

本版采用 Forward Deployed Engineering 的现场闭环：先审计真实拍摄目标，再用结构、时间轴、图像/视频匹配和运镜差异做评测，最后形成可交接、可恢复的交付结果。普通用户路径保持“打开 → 输入事件/菜品/场景 → 一键生成 → 查看结果”；只有打开专业输出后，才显示“FDE 现场交付卡”。

交付卡把本次结果整理为六项：交付目标、当前状态、验收门、参考与连续性、下一步、恢复点，并补充图片关键帧与视频分镜的交接说明。它读取现有校验器、运行记录和检查点，不上传现场素材、不引入后台服务，也不把 FDE 变成新的 Skill。它的用途是让拍摄者或协作者知道“这次结果能否交接、还缺什么、失败后从哪里恢复”。

## 数据与安全

HTML 无外链资源、遥测、上传或联网 API，且用内容安全策略关闭网络连接。普通输入只留在内存；品牌知识库仅写入当前浏览器的本机存储，并可随时导出或删除；导入文件按 JSON 读取，不执行代码；输出用纯文本呈现。100 KB 为导入上限，所有文本字段上限 2000 字。

导出的 JSON/TXT 可能包含用户填写的经营信息，请保管在本地。复制按钮只在点击时写入系统剪贴板；若系统启用了剪贴板同步，行为由操作系统管理，本页不主动上传。不要填写凭据或无关隐私资料。

本仓库发布文件按 Public 分类；用户课堂截图、原会话、表单输入和个人资料仍按 Unknown/Sensitive 留在本地，不进入 GitHub。ZIP 不包含课堂截图、视频、个人路径、账户配置或第三方代码。公开仓库只提供通用工具、规则和示范配置。

## 模块与扩展

单 HTML 内按边界组织：`SayelfFood` Core → 菜品 `DISHES` / 平台 `PLATFORMS` 数据 → 图片/视频文本编译 → UI / 本地导入导出 → 品牌知识库适配层。Core 不访问 DOM、存储或网络；品牌库只由 UI 适配层写入本机存储，可从 HTML 第一段 script 单独提取 Core 运行。真人秀、ASMR、配乐等开关可关闭；没有必须安装的第三方插件。

GSAP Motion Layer 是 UI 的共享能力，不是新的 Skill，也不进入 Core。页面暴露 `globalThis.SayelfMotion`（`reveal(targets, options)`、`reset(targets)`、`engine`、`available`、`prefersReducedMotion`）；宿主已经注入 `globalThis.gsap` 时直接复用其 `fromTo/to/context` 能力，独立 HTML 不加载 CDN 或外部脚本，未注入时使用同一入口的原生降级，用户开启减少动效时自动停用。后续 Skill 只调用这层，不重复设计动效底座。

配置格式为 `sayelf-food-video/v1`（输出 schema 为 `sayelf-food-video/v1.5`），输出 API 为 `SayelfFood.compile(input)`；成功包含 `shots,imageFrames,imagePrompt,videoPrompt,warnings,meta`，结构错误返回 `state: ERROR` 与 `errors`。`workflowMode` 默认 `dynamic`，`meta.eventFirst`、`meta.eventSupplied`、`meta.shotCountSource` 和 `meta.shotCountReason` 记录事件是否先决定节点；`meta.workflow` 记录本次内容触发的角色、依赖和判断信号，`meta.brief/derivedFields` 记录可选表达覆盖，`meta.productionCard` 记录料理卡与连续性锚点，每镜包含 `movement/edit/sfx/vfx`；调用品牌档案时，`input.brandProfile` 和 `meta.brandProfile` 记录本次使用的品牌上下文。内容需人工核对时状态为 `NEEDS_REVIEW`。JSON 下载只存输入与版本，避免把旧结果误当新结果；品牌库另用 `sayelf-food-video/brand-kb/v1` 管理。导入后重新生成。普通模式默认隐藏四要素、校验、母结构和配置工具，专业用户展开后才显示。

中英文界面使用 HTML 内嵌的本地语言资源，不加载翻译服务；Core 先生成唯一的镜头编号、时间轴和工艺节点，语言适配器只翻译展示层和内置建议，图片关键帧与视频分镜仍共享同一组 `id/start/end`。生成记录是本次页面会话内存，不写入浏览器存储，关闭页面即清除。

画面比例支持 `自动匹配`、`9:16`、`3:4`、`16:9`、`4:5`。自动匹配按平台编辑默认值选择：视频号、抖音和通用竖屏为 9:16，小红书为 3:4；最终输出会在图片 Prompt、视频 Prompt 和分镜元数据中保持一致。

添加新菜品可替换词库；添加平台只需编辑建议数据，不改故事与证据规则。平台画幅和节奏为产品的编辑默认值，不是官方强制要求或推荐算法结论。云渲染若后续接入，应位于外部适配层，须重新做构建决策与数据边界审查。

## 版本更新约定

以后每次功能或规则更新都递增版本号，并同步更新 HTML、SKILL、README、验证记录和 ZIP 商品包。README 顶部保留当前版本号与日期；本节只记录每一版的重点变化，便于用户快速判断是否需要替换文件。版本号采用 `主版本.次版本.修订号`：新增功能递增次版本，兼容性或文字修正递增修订号；若配置结构不兼容，必须在 README 和验证记录中明确说明。
